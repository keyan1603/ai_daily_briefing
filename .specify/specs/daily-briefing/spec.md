## Overview

A multi-agent AI system delivered as a Next.js web application that provides a personalised, hyper-local morning briefing to a user. The system fans out to independent data agents (weather, news, holiday) and then synthesises their output through a set of parallel Claude AI sub-agents to produce clothing recommendations, safety assessments, greetings, office advice, and a news summary — all assembled into a single cohesive briefing card UI.

---

## Problem Statement

A user starts their day needing multiple pieces of contextual information: what the weather is, what is happening locally, whether it is a holiday, and what to wear and how to plan. Today this requires opening four or five separate apps. The Daily Briefing collapses all of this into a single, AI-synthesised view that is delivered with one click and degrades gracefully when any data source or AI service is unavailable.

## User Stories

### US-01 — Location-Aware Briefing Request

**As a** user opening the app in a browser,  
**I want to** click a single button and grant location permission,  
**So that** the system can deliver a briefing that is specific to my city, state, and country without me having to enter any information manually.

**Acceptance Criteria:**
- [ ] On page load, the UI shows a "Get My Briefing" call-to-action button.
- [ ] Clicking the button triggers the browser Geolocation API. The user is prompted to grant permission.
- [ ] If permission is denied, a descriptive error state is shown. The app does not crash.
- [ ] The resolved coordinates (lat/lon) are reverse-geocoded to produce `city`, `state`, `country`, and `countryCode`.
- [ ] The resolved location is displayed in the UI (e.g., "Chennai, Tamil Nadu, India").
- [ ] Location data is never persisted — it exists only for the lifetime of the current request.

---

### US-02 — Real-Time Weather Display

**As a** user who has granted location access,  
**I want to** see the current weather conditions for my location,  
**So that** I can make decisions about what to wear and whether to go outside.

**Acceptance Criteria:**
- [ ] The weather card displays: current temperature (°C), feels-like temperature (°C), humidity (%), wind speed (km/h), UV index, precipitation (mm), and a human-readable condition description with an icon.
- [ ] A 5-day forecast strip is shown below the current conditions, with max/min temp, precipitation probability, and a weather icon per day.
- [ ] Weather data is fetched from Open-Meteo. No API key is required.
- [ ] Weather data is cached for 15 minutes to avoid redundant API calls on re-renders.
- [ ] If the weather API is unavailable, a rule-based default weather object is used and the briefing continues to render.

---

### US-03 — Localised News Feed with AI Ranking

**As a** user in a specific city,  
**I want to** see the top 3 most locally relevant news stories,  
**So that** I am informed about what is happening in my area without having to sift through national noise.

**Acceptance Criteria:**
- [ ] Up to 3 news articles are displayed, ranked by local relevance (city > state > national > weather/safety > business).
- [ ] Each article shows: headline, 2–3 sentence summary, source name, publication time, and a sentiment badge (positive / neutral / negative).
- [ ] **Path A (preferred):** If `NEWSDATA_API_KEY` is set, real articles from NewsData.io are fetched and then re-ranked and sentiment-labelled by a Claude sub-agent.
- [ ] **Path B (fallback):** If no NewsData key is set, a Claude sub-agent generates 3 plausible, realistic local news articles using known real institutions and landmarks for the user's city.
- [ ] **Path C (static fallback):** If Claude is also unavailable, 3 static demo articles are returned. The app does not crash.
- [ ] The news source path (`newsdata` / `ai-generated` / `static`) is recorded in `AgentSources.news`.

---

### US-04 — AI Clothing Recommendation

**As a** user who knows the weather but not what to wear,  
**I want to** receive a specific outfit recommendation based on today's conditions and whether it is a workday, weekend, or holiday,  
**So that** I can get dressed efficiently and appropriately.

**Acceptance Criteria:**
- [ ] The clothing card shows: a one-line outfit summary, a list of 2–4 specific clothing items, a list of accessories, a 2-sentence reasoning paragraph, a suggested colour palette, and boolean flags for umbrella / jacket / raincoat.
- [ ] The recommendation is generated by a Claude sub-agent that receives temperature, feels-like temperature, weather description, humidity, UV index, wind speed, and day type (workday / weekend / holiday + holiday name).
- [ ] If Claude is unavailable, a rule-based fallback generates a coherent recommendation using the same inputs (hot ≥ 30 °C, cool < 22 °C thresholds).
- [ ] The source (`ai` / `fallback`) is recorded in `AgentSources.clothing`.

---

### US-05 — Safety Assessment

**As a** user about to leave the house,  
**I want to** receive a safety level indicator and any relevant alerts,  
**So that** I can make an informed decision about outdoor plans and take appropriate precautions.

**Acceptance Criteria:**
- [ ] The safety card shows: a safety level (`safe` / `caution` / `warning` / `danger`), a one-sentence summary, and a list of 1–3 specific, actionable alerts.
- [ ] Safety is assessed from **both** weather conditions and news sentiment (negative news count + severe weather code + high UV index all influence the level).
- [ ] A Claude sub-agent receives weather data and news headlines with sentiment tags to produce the assessment.
- [ ] If Claude is unavailable, a rule-based fallback assesses safety from weather code (≥ 95 = warning), UV index (≥ 9 = caution), and negative news count.
- [ ] The source (`ai` / `fallback`) is recorded in `AgentSources.safety`.

---

### US-06 — Personalised Greeting and Day Context

**As a** user opening the briefing,  
**I want to** be greeted warmly with a message that reflects the day type and my city,  
**So that** the experience feels personal rather than generic.

**Acceptance Criteria:**
- [ ] A greeting message (2 sentences max) is displayed at the top of the briefing.
- [ ] The greeting is time-aware (Good morning / Good afternoon / Good evening) and day-type-aware (workday, weekend, or named holiday).
- [ ] A one-sentence "day context" line follows the greeting, describing the energy or mood for the day based on weather.
- [ ] A Claude sub-agent generates the greeting and day context, with cultural awareness for the user's country (India-aware by default).
- [ ] If Claude is unavailable, a rule-based fallback generates a coherent greeting using the same inputs.
- [ ] The source is recorded in `AgentSources.greeting`.

---

### US-07 — Office / Day Advice

**As a** user heading to (or staying away from) the office,  
**I want to** receive one actionable piece of daily advice,  
**So that** I can start my day with a clear intention.

**Acceptance Criteria:**
- [ ] A single sentence of office or day advice is displayed.
- [ ] On a workday, the advice is work-focused (traffic, hydration, productivity framing).
- [ ] On a weekend or holiday, the advice is rest or leisure focused.
- [ ] Rain detection influences commute advice ("leave earlier").
- [ ] A Claude sub-agent generates the advice. A rule-based fallback is available.
- [ ] The source is recorded in `AgentSources.officeAdvice`.

---

### US-08 — News Summary

**As a** user who wants the key takeaway from the news,  
**I want to** read a 2-sentence prose summary of today's top stories,  
**So that** I can stay informed without reading each article.

**Acceptance Criteria:**
- [ ] A 2-sentence news summary in flowing prose (no bullet points) is displayed above or alongside the news article cards.
- [ ] The summary is generated by a Claude sub-agent from the article titles of the ranked news.
- [ ] If Claude is unavailable, a rule-based summary lists the top 2 article titles in a readable sentence.
- [ ] The source is recorded in `AgentSources.newsSummary`.

---

### US-09 — Agent Pipeline Visualisation

**As a** user waiting for the briefing to load,  
**I want to** see which agents are running and which have completed,  
**So that** I understand the system is working and know roughly how long to wait.

**Acceptance Criteria:**
- [ ] A pipeline component shows each agent (Weather Agent, News Agent, Clothing Agent, Safety Agent, Orchestrator) with a live status indicator: `running` → `done` / `error`.
- [ ] Agents that resolve early show `done` while others continue running.
- [ ] On error, the failed agent shows an `error` state. Other agents that succeeded continue to show their results.
- [ ] The pipeline component disappears (or collapses) once the briefing is fully rendered.

---

### US-10 — Holiday Detection

**As a** user in a country where public holidays affect my day,  
**I want** the briefing to detect and acknowledge public holidays,  
**So that** greetings, clothing advice, and office advice are all adjusted appropriately.

**Acceptance Criteria:**
- [ ] If `CALENDARIFIC_API_KEY` is set, the system checks for public holidays on today's date for the user's country code.
- [ ] If a holiday is detected, `isHoliday: true` and `holidayName` are passed to all sub-agents.
- [ ] Holiday status affects: greeting tone, office advice content, and the `isOfficeDay` flag.
- [ ] If no Calendarific key is set, holiday detection is silently disabled. The briefing continues to render normally.
- [ ] Holiday status is included in the final `BriefingResponse.holiday` object.

---

### US-11 — Architecture Diagram

**As a** developer or curious user exploring the app,  
**I want to** see a visual diagram of the agent-to-agent communication architecture,  
**So that** I can understand how the system works and how data flows between agents.

**Acceptance Criteria:**
- [ ] An interactive or static architecture diagram is embedded in the UI.
- [ ] The diagram accurately reflects the current pipeline: Browser → `/api/briefing` → `[/api/weather, /api/news, Calendarific]` → `/api/recommend` → `[5 sub-agents]` → Final Briefing.
- [ ] The diagram is updated whenever a new agent is added or removed from the pipeline.

---

### US-12 — Graceful Degradation Under Failure

**As a** user whose briefing triggers during an API outage,  
**I want** the app to still deliver a useful briefing,  
**So that** I am not left with a broken or empty screen.

**Acceptance Criteria:**
- [ ] If any single external API (weather, news, Calendarific, Claude) is unavailable, the remaining agents continue.
- [ ] Every agent module has a documented rule-based fallback that produces coherent, context-aware output.
- [ ] The `sources` field in `BriefingResponse` reflects which modules used AI vs fallback for full transparency.
- [ ] No uncaught promise rejection reaches the user. All errors are caught, logged, and resolved to a fallback.
- [ ] Timeouts are configurable via environment variables: `WEATHER_TIMEOUT_MS`, `NEWS_TIMEOUT_MS`, `RECOMMEND_TIMEOUT_MS`, `AI_TIMEOUT_MS`.

## Data Model Summary

| Entity | Key Fields |
|---|---|
| `Location` | lat, lon, city, state, country, countryCode, locality? |
| `WeatherData` | temperature, feelsLike, humidity, windSpeed, weatherCode, description, icon, uvIndex, precipitation, isRaining, forecast[] |
| `WeatherForecast` | date, maxTemp, minTemp, precipitationChance, weatherCode |
| `NewsArticle` | title, description, url, source, publishedAt, sentiment, category, relevanceScore |
| `HolidayInfo` | isHoliday, holidayName?, holidayType? |
| `ClothingRecommendation` | outfit, items[], accessories[], reasoning, colorPalette, umbrella, jacket, raincoat |
| `SafetyAssessment` | isSafe, level, summary, alerts[] |
| `AgentSources` | clothing, safety, greeting, officeAdvice, newsSummary, news — each `'ai' \| 'fallback'` |
| `BriefingResponse` | greeting, dayContext, weather, holiday, clothing, safety, news[], newsSummary, officeAdvice, generatedAt, location, sources |

## Agent Architecture

```
Browser
  └── POST /api/briefing  (Orchestrator)
          ├── GET /api/weather          → WeatherData
          ├── GET /api/news             → NewsArticle[]  (Path A: NewsData.io → Path B: AI → Path C: Static)
          └── GET Calendarific          → HolidayInfo
                    ↓ (all three run in parallel via Promise.allSettled)
          POST /api/recommend           (Recommendation Orchestrator)
                    ├── Sub-Agent A: Clothing Recommendation  → ClothingRecommendation
                    ├── Sub-Agent B: Safety Assessment        → SafetyAssessment
                    ├── Sub-Agent C: Greeting & Day Context   → { greeting, dayContext }
                    ├── Sub-Agent D: Office Advice            → { officeAdvice }
                    └── Sub-Agent E: News Summary             → { summary }
                              ↓ (all five run in parallel via Promise.allSettled)
                    Final BriefingResponse JSON
```

## Out of Scope (v1.0)

- User accounts, authentication, or saved preferences.
- Push notifications or scheduled briefings.
- Multi-language support (English only in v1.0).
- Historical briefing storage or replay.
- Native mobile app (web-only in v1.0).
- Traffic or commute time data.
- Calendar integration.
